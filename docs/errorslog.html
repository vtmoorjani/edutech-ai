Root cause

Hit during initial Vercel deploy via v0. The user's ANTHROPIC_API_KEY belongs to an Anthropic API account with $0 balance. Confusion factor: the user has a Claude Pro subscription on claude.ai ($100/mo), but that pays for the browser product — it does not grant API credits. API billing lives at console.anthropic.com/settings/billing and is a separate ledger.

Fix (pending user decision)

Two options:
A. Add API credits at console.anthropic.com/settings/billing (≥ $10 recommended for MVP). No code change. Propagation takes 1–2 minutes.
B. Migrate to the Vercel AI Gateway (v0 offered an in-place rewrite). Bills usage to Vercel instead. Trade-off: rewrites lib/anthropic.ts off the official SDK, would need to re-prove prompt caching and Zod-validated messages.parse() structured outputs work via the Vercel AI SDK's generateObject shape.

Status (2026-05-08)

Still unresolved. The low-credit-balance branch v0 shipped (PR #1, merged to main as 9091490) added unrelated features (email/password auth, plans listing, save-flow fixes) but did not swap the AI provider — lib/anthropic.ts still imports @anthropic-ai/sdk and the deployed Vercel build will hit the same 400 on the next Claude call. User must still complete option A or B above.

Anthropic SDK: "Could not resolve authentication method" 2026-05-08 · config
Symptom
Could not resolve authentication method. Expected one of apiKey, authToken, credentials, config, or profile to be set. Or for one of the "X-Api-Key" or "Authorization" headers to be explicitly omitted
Root cause

web/.env.local existed but was an empty file (0 bytes). The user thought they had pasted the key, but the file got created empty (likely touch-style, not the cp .env.example .env.local the docs called for). The Anthropic SDK reads process.env.ANTHROPIC_API_KEY at request time and threw because nothing was set.

Fix

Re-wrote .env.local with the full template (Anthropic + Supabase + PostHog placeholders), instructed user to paste their key after ANTHROPIC_API_KEY= and restart the dev server (Next.js only loads env files at startup).

Where

web/.env.local

Build: useSearchParams() Suspense bailout on /roadmap 2026-05-08 · build
Symptom
useSearchParams() should be wrapped in a suspense boundary at page "/roadmap"
Root cause

Next.js 16 statically prerenders client components by default. useSearchParams() reads request data, so it triggers a CSR bailout — and that bailout is only legal inside a Suspense boundary.

Fix

Split app/roadmap/page.tsx into a thin default-exported wrapper that renders <Suspense fallback={...}><RoadmapInner /></Suspense>, and moved all hooks (including useSearchParams) into RoadmapInner.

Where

web/app/roadmap/page.tsx

TypeScript: zodOutputFormat signature mismatch 2026-05-08 · build
Symptom
lib/anthropic.ts(36,44): error TS2554: Expected 1 arguments, but got 2.
Root cause

Called zodOutputFormat(args.schema, "result") as if it accepted a name argument. Per the SDK signature in node_modules/@anthropic-ai/sdk/helpers/zod.d.ts, it takes only the Zod schema: function zodOutputFormat<ZodInput extends ZodType>(zodObject: ZodInput): AutoParseableOutputFormat<...>

Fix

Removed the second argument. zodOutputFormat(args.schema).

Where

web/lib/anthropic.ts:36

Git: .env.example accidentally ignored by .env* rule 2026-05-08 · config
Symptom
The following paths are ignored by one of your .gitignore files:
.env.example
Root cause

Default Next.js .gitignore uses a blanket .env* glob to keep secrets out of git, but that also matches .env.example — which is a non-secret template that should be committed so future clones know what env vars to set.

Fix

Added !.env.example exception under the .env* rule. Verified .env.local remained ignored before committing.

Where

web/.gitignore:34-35

Runtime risk: Supabase middleware crashes when env unset 2026-05-08 · runtime
Symptom

Anticipated, not yet observed. proxy.ts ran on every request and called createServerClient(process.env.NEXT_PUBLIC_SUPABASE_URL!, ...). Without those env vars, every page would 500 — blocking the AI flow until Supabase was set up.

Root cause

Non-null assertion (!) lies to TypeScript but doesn't change runtime — passing undefined to createServerClient throws.

Fix

updateSession now reads the env vars into locals; if either is missing, it returns NextResponse.next() immediately. The whole app (except auth/save/feedback) works without Supabase.

Where

web/lib/supabase/middleware.ts:8-13
